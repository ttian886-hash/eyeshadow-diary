# v302: data recovery and automatic sync boundaries

Prepared for review; production remains v301 until publication is authorized.

## Changes

- Automatic receive compares cloud contents as well as revision tokens. A changed document with a reused token follows normal apply/conflict rules rather than being silently ignored.
- Automatic upload transactions compare the server contents with the captured baseline as well as its revision. Changed server contents cannot be overwritten under a reused token.
- Listener callbacks, delayed receives, transaction writes and upload confirmations are bound to the authentication connection epoch. Stopping sync invalidates pending session callbacks.
- Imports reject duplicate history identities, duplicate selected shades, malformed selections and fractional/unsafe usage counts before replacing storage. Historical notes and references to removed products remain supported; counts are never reconstructed from incomplete history.

## Validation

38 application/state checks, 14 isolated import checks and 14 mocked Firestore checks passed (66 total). Existing checks cover date boundaries, active/all colour scopes, count restoration, failed writes and complete save/edit/delete roundtrips. New cases cover reused revisions, late account changes, stale listeners and invalid imports. JavaScript parse and whitespace checks passed.

## Remaining acceptance

No real two-device Firebase test or physical-device backup transfer was performed. Test fixtures do not touch the user's cloud records. Manual upload/download account-transition behavior was reviewed but is not covered by the new automatic-sync session guards; physical dual-device and account-switch acceptance remains required. No visual layout change is proposed.
