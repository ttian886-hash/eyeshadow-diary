# v300 review

Prepared as a review-only branch. Production stays v299 until publication is authorized.

## Changes

- Recording product options show text labels inside the existing collapsed menu.
- Selected shade names show a small checkmark as well as the existing background/pressed state.
- Shade usage figures are more readable, with aligned numeric glyphs.
- Backups without per-shade counters now correctly record newly saved uses. Earlier unknown shade counts are never fabricated; unsafe deductions are rejected.
- Homepage keeps its approved images and 1.4 mobile proportions. Responsive WebP derivatives are used with PNG fallback. Display-image totals: 6,547,398 bytes original; 226,902 bytes at 640px; 1,026,482 bytes at 1280px. These are image payload sizes, not measured load-time improvements or total app download sizes.
- New image assets are included in the v300 offline cache.

## Checks

- 24 app checks, 8 mocked cloud checks, and 10 isolated backup-import checks passed.
- All inline app and preview scripts parse. All cache entries exist. All image variants fully decode.
- Before/after preview includes 320/390/768px widths, representative single/duo/quad/12/60-shade layouts and long names. The preview browser reported 33/33 geometry checks passed (11 scenarios at each of 320/390/768px), checking horizontal overflow and panel bounds. These are geometry checks, not a complete touch/keyboard visual acceptance.
- Image blob hashes must match local git hashes before a review branch is created.

## Limits

The automated layout checks detect horizontal overflow and panel bounds; they do not replace touch-device or screen-reader tests. Firebase and file-import checks use isolated mocks, not the owner’s two physical devices or live cloud data. No claim of universal 10/10 quality is made.

Run from the repository root:

```sh
node audit/acceptance.cjs
node audit/cloud-sync.cjs
node audit/backup-import.cjs
```
